## Контракт и ресурсные ограничения

Переносимый профиль принимает непустые плотные вещественные матрицы
NumPy/PyTorch на CPU, `float32`/`float64`, явный целый ранг, локальный seed.
Результат хранит `U`, `S`, `Vh`, исходную форму и число компонент. Численный
ранг относится к возвращённому спектру; порог указан отдельно. Обучающие
координаты равны `U * S`, новые строки преобразуются как `X_new @ Vh.T`.
Порядок имён признаков проверяется при загрузке и проекции; без имён
действует явно документированный позиционный порядок.

Перед вычислением проверяются бюджеты входа, результата и оценочных рабочих
массивов. Загрузка сначала разбирает ограниченные заголовки NPY, проверяет
байтовые размеры и согласованность форм, затем применяет бюджет материализации
и матриц Грама по этим заголовкам. Значения метаданных не используются как
единственное доказательство допустимого объёма. Числовые массивы хранятся
без pickle; версия, схема, dtype, конечность, ортогональность и контрольные
суммы проверяются. Запись выполняется через уникальный временный файл
в том же каталоге и атомарную замену конечного пути.

Бюджет оценочных рабочих массивов не является жёстким системным лимитом
или измеренным пиком BLAS/LAPACK. API не меняет число потоков и не гарантирует
остановку текущего процесса по времени. Для жёстких требований потребитель
применяет отдельный процесс с системными ограничениями и сроком исполнения.
Вычислительное ядро не зависит от FEDOT и не меняет потребительские проекты.
GPU, RPC, CUR/Tucker в переносимом формате и подтверждение качества обучения
не входят в этот профиль.

## Протокол измерений

```bash
python -m pip install '.[experiments]'
python experiments/two_sided_run.py --shape 12 8 --shape 8 12 --rank 2 --true-rank 5 --seed 17 --repeats 1 --warmup 0 --isolated-memory --output cpu-protocol.json
```

Каждый метод каждого повтора выполняется в новом процессе. Измеряются
пик RSS процесса, исходный RSS после создания входа и превышение исходного
уровня. На Windows используется `peak_wset`, на Linux/macOS — системный
максимум RSS; значения приведены к байтам. Дополнительно RSS опрашивается
через psutil каждые 5 мс. Время вычисления в процессе и расходы запуска/передачи
указаны отдельно. Ограничение процесса — по умолчанию 30 с, максимум 60 с.

Этот пик включает библиотеки, вход, прогрев, факторизацию и реконструкцию;
его нельзя выдавать за память только рабочих тензоров. Выборочный RSS может
пропустить короткий пик. `tracemalloc` отдельно измеряет только Python-выделения;
`peak_native_bytes=null` прямо обозначает отсутствие отдельного измерения
нативных выделений. Оценка рабочих массивов записана отдельным полем.

Сохранены контрольная сумма общего входа, seed данных и метода, версия
протокола, ревизия, признак изменённых исходников, хеш текущего кода и версии
зависимостей. Исторические материалы не изменены. Проверка малого протокола
не даёт основания заявлять ускорение за пределами измеренной области.

## Оставшаяся приёмка

Нужны подтверждённый правообладателем текст лицензии, включение его в wheel
и sdist и успешный фактический CI для согласованной матрицы. До этого #37
и приёмка выпуска остаются открытыми. Распределённые функции имеют отдельный
профиль PyTorch >=2.4 и штатный отказ при отсутствии нужных API; локальная
проверка импорта на PyTorch 2.2 не доказывает распределённое исполнение.
Перед окончательной сборкой удаляются отслеживаемые `__pycache__` и
`tdecomp.egg-info`; временные метаданные, которые setuptools создаёт во время
сборки, не являются исходниками проекта.

Документ прошёл заключительную редактуру по `edit-russian-technical-text`:
имена API, файлов, команд и буквальные значения сохранены без перевода.
