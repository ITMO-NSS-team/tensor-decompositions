# tensor-decompositions

`tdecomp` предоставляет SVD, CUR, разложения Tucker и CP, а также оптимизатор TensorGRaD.
Переносимая вычислительная граница `tdecomp.api` предназначена для плотной
вещественной SVD на CPU; у остальных модулей свои параметры и результаты.

## Установка и зависимости

```bash
python -m pip install .
python -m pip install '.[test,experiments]'
python -m pytest -q
```

Для работы из исходников можно использовать `python -m pip install -e .`.
Метаданные определены только в `pyproject.toml`; `setup.py` — совместимая точка
входа сборки. Версия пакета сохранена: `0.2.4`.

| Профиль | Зависимости и назначение |
|---|---|
| Базовый | Python 3.10–3.12, NumPy 1.26.4–1.x, TensorLy 0.9.x, PyTorch 2.2–2.5 |
| `tensorflow` | TensorFlow 2.16.2–2.16.x; необязательная ветвь `utils.no_grad` |
| `distributed` | PyTorch 2.4–2.5; асинхронные распределённые контрольные точки |
| `visualization` | Matplotlib для графиков |
| `experiments` | Matplotlib, Pandas и psutil для таблиц, графиков и измерений |
| `training` | Transformers, Accelerate, Datasets, Evaluate и MLflow для внешних сценариев обучения |
| `profiling` | Дополнительные инструменты NVIDIA; профилирование требует подходящего PyTorch и устройства |

Локальная приёмка выполняется на Python 3.10, PyTorch 2.2.0, NumPy 1.26.4,
TensorLy 0.9.0, CPU. CI дополнительно проверяет Python 3.12/PyTorch 2.5.1 и
штатную ветвь `no_grad` с TensorFlow 2.16.2. Это не подтверждает всю область
тензорных методов TensorFlow, распределённое обучение или GPU.
Файл `uv.lock` закрепляет разрешённые зависимости; выбор дополнительных
профилей остаётся явным, например `uv sync --extra test`.

Импорт `tdecomp` не выбирает backend TensorLy, не меняет `WANDB_MODE`,
глобальные генераторы случайности или настройку журналирования. Обучающие
модули импортируются при обращении к ним. Для классического API вызывающая
программа сама выбирает backend; переносимый API выбирает его по типу входа
в пределах текущего потока и возвращает прежнее состояние.

## Переносимая SVD

```python
import numpy as np
from tdecomp.api import SVDMethod, SVDRequest, compute_svd, save_svd, load_svd

X = np.random.default_rng(7).normal(size=(20, 8)).astype(np.float64)
names = tuple(f"feature_{i}" for i in range(8))
request = SVDRequest(rank=3, method=SVDMethod.EXACT, seed=7, feature_names=names)
result = compute_svd(X, request)
X_approx = result.reconstruct()
scores = result.transform(X, feature_names=names)
assert np.allclose(scores, result.U * result.S)

save_svd(result, "svd.npz")
restored = load_svd("svd.npz", feature_names=names)
```

Вход — непустой `numpy.ndarray` или плотный `torch.Tensor` формы `(m,n)` на CPU
с конечными значениями `float32`/`float64`. Тензоры с `requires_grad=True`,
целочисленные, комплексные, разреженные, пакетные и GPU-входы отклоняются.
Выход сохраняет backend и dtype входа; исходный массив не изменяется.

`rank` обязателен: положительное целое до `min(m,n)`, без `bool` и скрытого
выбора ранга. `SVDMethod` содержит только `EXACT`, `RANDOMIZED`, `TWO_SIDED`.
Случайные методы используют нормальные проекции, локальный `seed`,
`power` и `oversampling`. Для `EXACT` эти два параметра записываются в сведения
о запросе, но не влияют на точную SVD. Метод и ранг не подменяются автоматически.
Повтор одинакового запроса воспроизводит аппроксимацию в одном окружении;
знаки сингулярных векторов и базис кратных сингулярных значений не являются
универсально закреплёнными между реализациями BLAS/LAPACK.

Результат `SVDResult` содержит `U: (m,k)`, `S: (k,)`, `Vh: (k,n)`, исходную
форму, запрошенный ранг и `components=k`. `numerical_rank` считает значения
**возвращённого спектра**, превышающие `rank_threshold = eps * max(m,n) * S[0]`.
Это отдельная диагностика, а не оценка полного ранга исходного массива.
Нулевой вход даёт нулевой спектр и численный ранг 0 при сохранении `k` компонент.
`diagnostics` содержит метод, версии зависимостей, seed, время факторизации,
ошибку реконструкции, размеры и оценку рабочих массивов.

Стабильные ожидаемые отказы представлены `SVDContractError`, наследником
`ValueError`, с полем `code`: `invalid_request`, `invalid_rank`, `invalid_shape`,
`unsupported_input`, `unsupported_dtype`, `unsupported_device`,
`unsupported_layout`, `nonfinite_input`, `resource_limit`, `numerical_failure`,
`invalid_result`, `invalid_artifact`, `unsupported_artifact_version`,
`unsupported_backend`, `backend_mismatch`, `feature_order_mismatch`.
Реестр `CAPABILITIES` содержит только поддержанные методы и доступен для чтения.

`ResourcePolicy` ограничивает байты входа, выхода и оценку рабочих массивов
до вычисления. При загрузке проверяются размер архива и заголовки NPY до
материализации массивов; при проекции новых строк применяются отдельные
бюджеты аргумента `resources`. Оценка памяти не является измеренным пиком
и не ограничивает выделения нативной BLAS/LAPACK. Число потоков задаёт
приложение; API лишь записывает `torch_threads` и не меняет его. Жёсткий
срок исполнения и лимит памяти обеспечиваются вызывающим процессом:
запускать отдельный процесс, передавать числовой вход, применять системные
ограничения и прекращать процесс при истечении срока. Встроенного сервиса
или гарантий остановки вычисления внутри текущего процесса нет.

`save_svd` атомарно записывает один NPZ-файл с числовыми массивами и метаданными
JSON версии 1. Python-объекты и pickle не допускаются. `load_svd` проверяет
версию, схемы, формы, dtype, конечность, ортогональность, спектр, контрольные
суммы и порядок признаков. Загрузка по умолчанию возвращает NumPy; для PyTorch
указать `backend="pytorch"`. Если имена признаков сохранены, загрузка и
`transform` требуют того же упорядоченного кортежа. Без имён действует
позиционный порядок; перестановка столбцов должна быть проверена потребителем.
Контрольные суммы обнаруживают повреждение и не подтверждают авторство файла.

Для потребительского проекта достаточно вызвать `compute_svd` в его адаптере
и хранить `Vh` вместе с порядком признаков. Новые строки преобразуются как
`X_new @ Vh.T`; обучающие координаты равны `U * S`. Зависимость от FEDOT,
SamplingZoo или IndustrialTS в ядро не добавляется. CUR и Tucker имеют другую
семантику и не объявлены совместимыми с этим форматом.

## Классические разложения

```python
import numpy as np
import tensorly as tl
from tdecomp.matrix.functional import rsvd
from tdecomp.matrix.decomposer import CURDecomposition
from tdecomp.tensor.tucker import RSTHOSVDDecomposition
from tdecomp.tensor import CPDecomposition

with tl.backend_context("numpy"):
    X = np.random.default_rng(5).normal(size=(12, 8))
    U, S, Vh = rsvd(X, n_eigenvecs=3, random_state=5)
    assert U.shape == (12, 3)
    cur = CURDecomposition(rank=3)
    C, middle, R = cur.decompose(X)
    cur_approx = cur.compose(C, middle, R)
    tensor = np.random.default_rng(6).normal(size=(5, 4, 3))
    tucker = RSTHOSVDDecomposition(rank=(3, 2, 2), random_state=6)
    core, factors = tucker.decompose(tensor)
    tensor_approx = tucker.compose(core, factors)
    cp = CPDecomposition(rank=2, random_state=6)
    weights, factors = cp.decompose(tensor)
    cp_approx = cp.compose(weights, factors)
```

В `matrix.decomposer` доступны `SVDDecomposition`, `RandomizedSVD`,
`TwoSidedRandomSVD`, `CURDecomposition`; в `matrix.functional` — явные
обёртки `rsvd`, `r2svd`, `cur`. `n_eigenvecs` в обёртке задаёт ранг вызова;
остальные именованные параметры передаются конструктору. Неизвестные параметры
вызывают ошибку. Реестры `DECOMPOSERS`, `RANDOM_GENS`, `IMPORTANCE_GENS`
содержат только объявленные операции.

Целый ранг SVD, CUR и Tucker ограничивается размером оси. Дробь в `(0,1]`
означает долю соответствующего размера, с округлением вниз и минимумом 1.
`None` использует настроенный ранг; точная SVD без настройки возвращает полный
спектр, случайные методы могут выбрать ранг по своей оценке. Ранги пересчитываются
для каждого входа и не заменяют настройку объекта. Для Tucker доступны
`RPHOSVDDecomposition`, `RSTHOSVDDecomposition`, `RSTDecomposition`,
`HOOIDecomposition`; результат — `(core, factors)` с модальными факторами.

Для CP доступен `CPDecomposition`; результат — `(weights, factors)`, где
`weights` имеет форму `(rank,)`, а каждый фактор — `(mode_size, rank)`.
Целый ранг задаёт общее число CP-компонент и не ограничивается размером
отдельной моды. Дробный ранг задаёт долю от минимального размера входа
с округлением вниз и минимум одной компонентой; `None` выбирает минимальный
размер. Последовательность должна содержать одно значение либо одинаковое
число компонент для всех мод. Массивы сохраняют тип данных и устройство входа.
ALS решает невыпуклую задачу и не гарантирует оптимальную аппроксимацию;
`n_iterations_` показывает фактическое число шагов.

CUR возвращает `(C, middle, R)`, реконструкция равна `C @ middle @ R`.

В классическом API `set_conditioner(C)` решает задачу аппроксимации взвешенной
матрицы `X @ C` и возвращает правый фактор после обратного преобразования.
`C` должна быть численно обратимой квадратной матрицей либо ненулевой диагональю.
При усечении минимизируется взвешенная ошибка; правый фактор после коррекции
может быть неортогонален, а `S` относится к `X @ C`. Это не обычная SVD `X`.
Переносимый API такой режим не принимает.

`random_state` классического API принимает неотрицательное целое, локальный
`numpy.random.Generator` или `None`. Целое в повторном вызове заново задаёт
одинаковую последовательность, если передано аргументом `decompose`;
генератор, созданный конструктором или переданный явно, расходует своё состояние.
`None` создаёт локальную случайность и не изменяет глобальные NumPy/PyTorch RNG.
`lean_walsh` сохранён как имя с явным `NotImplementedError` и исключён из реестра
поддержанных генераторов; его прежняя формула не принималась как проверенный метод.

## TensorGRaD

```python
import torch
from tdecomp.grad_proj.tensorgrad import ParallelTG, ULTG

model = torch.nn.Linear(8, 4)
optimizer, scheduler = ParallelTG(model, "truncated_svd", rank=2)
loss = model(torch.ones(2, 8)).square().mean()
loss.backward()
optimizer.step()
scheduler.step()
```

`ParallelTG` и `ULTG` — совместимые фабрики: возвращают пару `(optimizer,
scheduler)`. Первая объединяет низкоранговую и разреженную ветви; вторая
последовательно проектирует градиент и его остаток. В обеих фабриках пара
`rank=(low_rank, sparse_ratio)` задаёт ранг низкоранговой ветви и долю
сохраняемых элементов разреженной ветви. Для `ULTG` разреженная ветвь
выполняется первой, но порядок аргументов пары остаётся тем же.
Скалярный ранг задаёт низкоранговую ветвь; доля разреженной ветви сохраняет
настроенное значение (по умолчанию `0.25` для `ParallelTG`, `0.1` для `ULTG`).
В `OptimizerConfig` параметры `rank`, `second_rank`, `sparse_ratio` и
`second_sparse_ratio` задают соответствующие ветви. Именованные параметры
фабрик имеют приоритет над значениями пары.
Фабрика `AdamW(model, ...)` возвращает пару `(torch.optim.AdamW, scheduler)`
для контрольного сравнения; также принимает прежние аргументы `svd_type`
и `rank`, которые не включают проекции в AdamW. Явная настройка доступна через
`TensorGRaDConfig`, `OptimizerConfig` и `setup_optimizer_and_scheduler`.
Поддержанные алгоритмы: `tensorgrad`, `tensorgrad_sum`, `adamw`, `sgd`.
Проекторы: `low_rank`, `structured_sparse`, `unstructured_sparse`; параметры
проверяются до первого шага. При смене проекции поддержана политика моментов
`reset`. Продолжение обучения требует сохранения модели, оптимизатора,
расписания и RNG; формат численной SVD не является контрольной точкой обучения.

## Воспроизводимый CPU-протокол

Для проверки обучения на одинаковых синтетических последовательностях
запустите команды из репозитория или распакованного sdist:

```bash
python -m pip install '.[experiments]'
python -m examples.tensorgrad_train --steps 3 --seed 17 --output tensorgrad-training.json
```

Пример сравнивает `AdamW`, `ParallelTG` и `ULTG` с одинаковыми начальными
весами и входами. JSON содержит потери, перплексию (perplexity) на отдельном контрольном
пакете, время обучения и размер тензорного состояния. Это проверка исполнения,
а не доказательство качества обучения внешней языковой модели.
Для CUDA явно укажите `--device cuda`. Запись в MLflow включается только
при передаче `--mlflow-uri`; для неё установите дополнительные зависимости
`training`. Вспомогательные функции измерений, таблиц и графиков находятся
в `examples`; адаптеры Transformers загружаются отдельно по запросу.

CPU-контейнер запускается командой `docker compose run --rm tdecomp`.
Профиль GPU: `docker compose --profile gpu run --rm tdecomp-gpu`.
Результаты сохраняются в `outputs` (путь переопределяется через `OUTPUT_DIR`);
GPU выбирается через `GPU_IDS`. Контейнер по умолчанию не использует внешние
модели, данные или сервисы. Сопоставление с PR #35 приведено в
[docs/audit/PR35_COMPARISON.md](docs/audit/PR35_COMPARISON.md).

Для сравнения разложений матриц используется отдельный протокол:

```bash
python -m pip install '.[experiments]'
python experiments/two_sided_run.py --shape 48 32 --shape 32 48 --rank 4 --true-rank 12 --seed 17 --repeats 3 --isolated-memory --output cpu-protocol.json
```

Протокол независимо задаёт целевой и истинный ранги, спектр `flat`/`geometric`
и шум `--noise`. Методы получают одинаковый вход каждого повтора и сравниваются
с оптимальной SVD того же целевого ранга. Время факторизации, реконструкции
и полной операции API разделены. `peak_python_traced_bytes` измеряет только
Python-выделения; пик нативной памяти оставлен `null`, оценка рабочих массивов
записана отдельно. `--isolated-memory` запускает отдельный процесс для каждого
метода и повтора и измеряет пик RSS всего процесса: на Windows используется
`peak_wset`, на Linux/macOS — системный максимум RSS, дополнительно каждые 5 мс
снимается RSS через psutil. Все величины приведены к байтам. В результатах
сохранены исходный RSS после создания входа, превышение этого уровня, отдельное
время вычисления в процессе и время запуска/передачи. Пик включает загрузку
библиотек, вход, прогрев и реконструкцию; он не является размером рабочих массивов
или пиком только тензорных выделений. Выборочная оценка RSS может пропустить
краткий пик. Срок процесса ограничен `--worker-timeout` (по умолчанию 30 с,
максимум 60 с). Каждая попытка имеет статус; автоматических повторных попыток
нет. Сохраняются seed, контрольная сумма входа, ревизия, признак изменённых
исходников, хеш текущего кода и версии зависимостей. Исторические CSV и рисунки
остаются историческими материалами и не переобозначаются как новые измерения.
Прохождение малого протокола подтверждает его исполнение, но не универсальное
ускорение и не качество обучения.

## Лицензия и выпуск

Исходные метаданные заявляли BSD, но текст и вариант лицензии отсутствовали.
До получения текста от правообладателя это ограничение остаётся открытым;
проверка выпуска требует включённый `LICENSE` и совпадение метаданных wheel
и wheel из sdist. Публикация PyPI разрешена workflow только при опубликованном
release после успешной приёмки и TestPyPI; push и Pull Request запускают проверки.
