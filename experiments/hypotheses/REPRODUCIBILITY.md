# Воспроизведение локальных серий

Протоколы H01–H12 — зафиксированные постановки. Метка `PLANNED / NOT RUN` относится к исходному документу, а не к текущему состоянию вычислений. Фактический статус определяется манифестом конкретного запуска и отчётом результатов. Исходные протоколы не редактируются по результатам теста.

## Окружение

Проверенный профиль: Python 3.10, PyTorch 2.2.0+cu121, torchvision 0.17.0+cu121, NumPy 1.26.4, TensorLy 0.9.0, Transformers 4.39.1. Для GPT-2 и Switch используются непосредственно проверенные нативные реализации Transformers этой версии. Локальный профиль зависимостей — `requirements-local.txt`; он отделён от общих необязательных зависимостей библиотеки. GitHub Actions проверяет этот профиль на CPU.

Команды ниже выполняются из корня репозитория; `python` означает интерпретатор проверенного окружения. Вычисления не запускаются автоматически при импорте или установке пакета.

```powershell
python -m pip install -r experiments/hypotheses/requirements-local.txt
python -m pip install -e '.[test,experiments]'
python -m pytest tests -q
```

## Данные и контрольные точки

`asset-lock.json` содержит точные ревизии и SHA256 моделей GPT-2, Switch-base-8 и WikiText-2. Подготовка ресурсов записывает локальные пути и контрольные суммы в отдельные документы происхождения; существующий файл с неверной суммой сохраняется и вызывает остановку.

```powershell
python experiments/hypotheses/prepare_real_assets.py --data ../audit/datasets
python experiments/hypotheses/prepare_real_assets.py --data ../audit/datasets --local-only
```

Для CIFAR-10 общий исполнитель создаёт разделы 40 000/2000/3000/5000 и три независимых 30-эпоховых эталона. Официальный тест не используется для их обучения. Снимки модели, оптимизатора, разделов и хеши сохраняются в каталоге запуска.

```powershell
python experiments/hypotheses/train_cifar_baseline.py --data ../audit/datasets/cifar10 --output ../audit/runs/cifar-baseline
```

H09 требует **отдельных свежих** контрольных точек: пять эпох с постоянной скоростью обучения и сохранённым состоянием оптимизатора. Общий 30-эпоховый эталон не подходит.

```powershell
python experiments/hypotheses/train_cifar_baseline.py --h09-warmup --data ../audit/datasets/cifar10 --output ../audit/runs/h09-warmup
```

## Порядок вычислений

Каждый реальный исполнитель сначала проходит независимые тесты и небольшой допуск, затем пробный запуск без окончательного теста. Только после этого выполняется основная серия. Полные команды сохраняются в манифестах; справка конкретного исполнителя показывает его обязательные пути и режимы.

Одновременно GPU использует один вычислительный процесс. На локальной RTX 4080 установлены лимиты 12 GiB видеопамяти и 24 GiB памяти процесса. Выделенная и зарезервированная память PyTorch записываются отдельно; эти величины не складываются. Windows/WDDM может не показывать память отдельного процесса, поэтому используется консервативная проверка всей занятой памяти устройства.

Результаты, контрольные точки и данные размещаются вне Git. Каждый новый запуск создаёт новый каталог; отрицательный результат, ошибка реализации или превышение ресурсов не перезаписываются успешным повтором. Снимки исходников и SHA фиксируют фактически исполненный код, включая ещё не опубликованные изменения рабочего дерева.

## Границы выводов

Проверки формул, весовой ошибки, качества сети, времени и памяти оценивают разные утверждения. Их нельзя объединять в подтверждение всей гипотезы. Три реальных эталона дают слабую оценку неопределённости; t-интервалы условны при приблизительной нормальности парных разностей. Повторы времени и отдельные изображения не увеличивают число независимых эталонов.

Для H10 физическое распределённое исполнение требует нескольких GPU; локальная постановка использует реальные трассы нативной модели и объявленную модель стоимости связи. Для H08 независимая база из 16 проб требует отдельного уточнения и собственной шумовой калибровки. Эти ограничения сохраняются в отчёте, даже когда отдельная вычислительная серия завершена.
